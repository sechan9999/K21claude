### 5.3 Root Cause Analysis

**OCR 오류 메커니즘** (이준석, 권영국, 송진호):
1. 투표함별 재확인표 데이터를 투표용지 총수로 중복 계산
2. Example: 투표함 500장 중 재확인 80장 → OCR 인식 실패로 5000장으로 증폭
3. 결과: 해당 후보 재확인율 16% → 160% 오류 발생

**선거 결과가 정확한 이유**:
- 재확인표 제외, 원래 투표수만 사용
- OCR 오류는 "재확인" 카운트에만 영향

## 6. Lessons Learned & Retrospective

### 6.1 What Went Well (Keep)

1. **PDF 직접 검증 접근법 효과적**
   - 이미지 기반 PDF에서 정확하게 데이터 추출 가능
   - pdfjs-dist + node-canvas 조합이 우수했음
   - 6개 표본으로도 전체 패턴 파악 가능했음

2. **Statistical Analysis로 이상 패턴 조기 발견**
   - K값(7.72)과 R²(0) 극값이 데이터 오류를 명백히 함
   - 통계적 불가능성이 문제 증거로 작용
   - 다른 데이터는 OK였을 가능성 시사

3. **체계적인 문서화**
   - 161줄 보고서로 전체 프로세스 기록
   - 후보자별 품질 등급 명확화
   - 지역별 진단 테이블로 추적 가능

4. **UI 업데이트로 사용자 혼란 방지**
   - 경고 메시지 변경 ("통계 이상" → "OCR 오류")
   - 대시보드에서 문제 데이터 명시
   - 차트 제거로 오도성 차단

5. **공식 데이터 검증 (득표수)**
   - 중앙선거관리위원회 CSV와 100% 일치 확인
   - 선거 결과 신뢰도는 보장됨

### 6.2 What Needs Improvement (Problem)

1. **원본 OCR 데이터의 저품질**
   - K21_대선_개표결과_상세.xlsx의 재확인표 데이터가 신뢰할 수 없음
   - 3명 후보 데이터가 심각하게 손상됨
   - 향후 데이터 수집 시 직접 검증 필수

2. **통계 모델의 한계**
   - 오염된 데이터에서 의미 있는 K값/R² 도출 불가
   - "통계적 이상 패턴"만으로는 근본 원인 파악 어려움
   - PDF 검증이 없었다면 원인 불명

3. **표본 크기 제약**
   - 6개 투표함만 검증 (전국 16,000+ 투표함 대비 0.04%)
   - 모든 지역을 전수 검증하기는 현실적으로 불가능
   - 대표성 검증 필요했음

4. **초기 탭 이름 오류**
   - "재확인표 분석" (분석은 안 함) → "재확인표 검증"으로 변경됨
   - 초기 설계 시 검증/분석 구분 부족

### 6.3 What to Try Next (Try)

1. **데이터 소스 다양화**
   - 중앙선거관리위원회 공식 CSV만 신뢰
   - 제3자 가공 데이터는 검증 후 사용
   - 원본 PDF 폼 병렬 수집

2. **자동화 검증 파이프라인**
   - render_pdf_page.mjs를 정기 실행 스크립트로 전환
   - 신규 데이터 입수 시 자동 OCR 검증
   - CI/CD 통합

3. **향상된 통계 모델**
   - 로버스트 회귀 (M-estimator) 적용 (이상치 제외)
   - 후보별 K값 분리 계산
   - 신뢰도 스코어(Confidence Interval) 추가

4. **사용자 교육**
   - 대시보드에 데이터 품질 설명 추가
   - "OCR 오류" vs "통계 이상"의 차이 명확화
   - 공개 이용자 가이드 작성

5. **향후 선거 대비**
   - 이번 검증 경험 축적
   - PDF 직접 검증 자동화 도구 개선
   - 실시간 모니터링 시스템 구축
